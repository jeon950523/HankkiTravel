# API 개요

API의 상세 계약은 백엔드 소스와 테스트를 기준으로 합니다. 아래는 포트폴리오에서 기능 흐름을 이해하기 위한 핵심 경계이며, 실제 운영 자격증명·관리자 주소·키 값은 공개하지 않습니다.

## 사용자 기능

| 범주 | 역할 |
| --- | --- |
| 여행·프로필 | 가족 구성원, 여행 조건, 식사 슬롯, 일정 상태를 다룹니다. |
| 관광·음식점 추천 | TourAPI 기반 관광·음식점 후보와 추천 근거를 제공합니다. |
| 지도·동선 | 좌표와 이동 부담 정보를 이용해 일자별 계획을 표시합니다. |

## 확인 가능한 관광 API 경계

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `GET` | `/api/tourism/live/restaurants` | 현재 조건에서 사용할 음식점 후보 조회 |
| `GET` | `/api/tourism/live/restaurants/{contentId}/decision-data` | 특정 음식점의 추천 판단 데이터 조회 |

## 운영 전용 동기화 경계

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `GET` | `/api/admin/tourism-sync/status` | 동기화 상태와 내부 호출 예산 확인 |
| `POST` | `/api/admin/tourism-sync/runs` | 승인된 운영자만 동기화 실행 |

관리자 동기화는 `ADMIN_SYNC_ENABLED=false`가 기본값입니다. 운영에서 활성화하더라도 서버 측 인증과 비밀값으로만 보호해야 하며, 프런트엔드 코드나 URL에 관리자 비밀번호를 넣지 않습니다.
